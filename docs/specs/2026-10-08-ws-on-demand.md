# WS 按需连接与 HTTP 预热兼容

## 已确认范围

本次只实施用户确认的方案 1、2、4：

1. 取消启动和本地会话注册时的无条件上游 WS 预热。只有实际等待 WS 的请求才建立连接；HTTP 会话不补连、不在响应后领取 WS。能力关闭时回收空闲连接，停止等待中的补连，正在执行的请求完成后退出；不得重放已提交请求。
2. HTTP 路径识别 `generate=false` 预热，本地返回完整终态与零用量，不向上游发起生成。复用现有 HTTP 续传底稿，下一次带本地响应 ID 的增量请求展开为完整输入；上游 HTTP 不携带 `generate` 或本地响应 ID。覆盖能力降级、显式 HTTP、冷启动、大请求及已证明未提交的安全回退入口。
3. UI 和实际路由使用同一份有效能力状态。过期 WS 能力按 HTTP 展示和路由；刷新失败的退避不得延长能力有效期；完整新快照不得保留已移除模型的旧 WS 标签。已保存的 HTTP 策略显示 HTTP。

明确不实施原方案 3：不根据模型能力改写 Codex provider 的 `supports_websockets`，不改用户全局 WS 偏好，不重启运行中的 Turbo 或 Codex。

## 验收边界

- 本地 WS 握手及 HTTP-only 预热：上游 WS 握手 0 次，HTTP 生成 0 次。
- 预热后的真实生成：HTTP 1 次，空输入和非空输入预热均可完成；上下文完整，传输专用字段不进入 HTTP。
- HTTP 与 WS 模型并行：HTTP 会话不预热，WS 模型正常复用自身连接。
- 能力从 WS 切到 HTTP：空闲连接回收；等待中的补连停止；已提交请求完成，HTTP 不重放。
- 取消、会话隔离、状态续传、精确未提交回退合同继续有效。
- 前端通过真实 DOM 检查 HTTP-only、过期与 WS 可用状态；不启动桌面实例。

## 实现约束

复用现有 Hybrid 连接池、HTTP worker、续传合并及能力缓存。保留连接容量上限、身份隔离、连接租约和续传移交。删除固定备用池及其专用验收，保留按需连接和资源归属的验证。

本地预热只保存本次 WS 会话的续传材料，不代表上游已缓存输入。客户端换连接后携带无法识别的响应 ID，仍按现有协议返回状态缺失，不猜测或重放历史。

能力更新可即时唤醒空闲会话与等待握手；缓存自然过期在下一次请求或空闲健康检查时处理，已发出的业务请求不被中途改路由。
